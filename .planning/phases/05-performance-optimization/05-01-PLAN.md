## Current State

GameViewport.renderEntitiesUnified() currently renders all entities in the world. It uses `isTileVisible()` for basic culling but:
- Checks visibility per-entity (O(n) cost)
- Still processes all entities for depth sorting
- No spatial acceleration for culling

SpatialIndex exists and provides O(1) insertion and fast range queries. Perfect for frustum culling integration.

## What Needs To Be Built

1. **FrustumCuller class**: Calculate screen frustum bounds with configurable margin
2. **AABB intersection**: Fast bounding box vs frustum tests
3. **Integration with SpatialIndex**: Query spatial index for candidates, then precise frustum test
4. **GameViewport integration**: Replace per-entity visibility checks with frustum culling

## Architecture Patterns

Per ARCHITECTURE.md:
- Use classes for stateful objects (FrustumCuller)
- Explicit property declarations with `!` for late initialization
- Keep files under 500 lines (RFC-0007)
- Type-safe coordinate handling

## Technical Notes

- Frustum = camera.worldView (Phaser.Geom.Rectangle)
- Margin = 10% prevents objects popping at screen edges
- SpatialIndex cell size (64px) works well with typical object sizes
- Cull early: before depth sorting, occlusion checks, or rendering
