## One-Liner

Established pseudo-3D visual foundation with type-safe coordinate systems, height-aware rendering, and dynamic depth sorting — transforming a fixed-layer 2D engine into a spatially-aware 2.5D presentation.

---

## What Was Built

### Phase 1: Foundation ✅

**Coordinate System Infrastructure**
- Branded types: `TileCoord`, `WorldCoord`, `DepthValue` with compile-time safety
- Anchor standard: `ANCHOR_BOTTOM_CENTER = { x: 0.5, y: 1.0 }` for consistent positioning
- Conversion utilities: `CoordinateConverters` namespace with 8 transformation functions

**Height & Footprint Registry**
- `HeightClassification`: flat/low/medium/tall with pixel ranges (0, 1-15, 16-31, 32+)
- `VisualPackMetadata`: complete visual configuration including `renderHeight`, `footprint`, `canOccludePlayer`
- `VisualPackRegistry`: registration and validation at mod load time
- Default visual packs: core:tree (tall, 48px), core:rock (low, 12px), core:berry_bush (medium, 20px)

**Spatial Indexing**
- `SpatialIndex`: uniform grid with 64px cells, O(1) insertion, sub-millisecond queries
- World coordinate queries and region-based lookups

**Note on Tile Rendering**: v0.1 uses **orthogonal square tiles** with Y-axis depth sorting for pseudo-3D effect. True isometric/diamond tile rendering (VIS-01) is **Out of Scope** — not implemented and not planned.

### Phase 2: Core Rendering ✅

**Depth Sorting System**
- `Pseudo3DDepthSorter`: dirty-flag optimized depth management
- Formula: `depth = (y + renderHeight) * 1000 + typePriority`
- Type priority: terrain(0) < resource/planted(1) < structure(2) < drop(3) < player(4)
- Batch processing and cached sorting for performance

**Shadow System**
- Height-based shadow sizing: flat=null, low=8×3px, medium=12×5px, tall=16×6px
- `createEntityShadow()`: factory with automatic size selection
- Shadow sync: positions and depths update with parent entities

**Unified Rendering Pipeline**
- Replaced fixed layers (0, 2, 3, 4, 7) with dynamic depth sorting
- `entitySprites` Map: unified container for all renderable entities
- `entityShadows` Map: shadow management for tall/medium objects
- Sprite pooling: reusable sprites (max 50) to reduce GC pressure
- Dual-mode rendering: new pipeline alongside legacy for safe transition

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Custom Y-sorting via Phaser depth | Avoid deprecated isometric plugins, no true 3D needed | ✅ Working, 60fps maintained |
| Height-based sorting vs Z-index | More intuitive for mod authors | ✅ Correct occlusion achieved |
| Single-container pipeline | Replace fixed layers for proper depth | ✅ Unified rendering working |
| Pattern-based visual pack fallback | VisualPackRegistry not yet in RuntimeContentIndex | ✅ Temporary solution functional |
| Branded types for coordinates | Compile-time safety, zero runtime overhead | ✅ Type-safe boundaries enforced |
| Bottom-center anchoring standard | Aligns gameplay position with visual position | ✅ Consistent positioning |
| Dirty-flag depth optimization | Only recalculate when positions change | ✅ Performance maintained |

## Known Limitations (v0.1)

1. **No dynamic occlusion**: Player behind objects doesn't trigger alpha fade (Phase 3)
2. **Pattern-based visual packs**: Hardcoded "tree"/"rock" detection instead of registry lookup (Phase 4)
3. **No performance benchmarks**: Baseline metrics not yet established (Phase 3)
4. **Legacy rendering still active**: Dual-mode for safety, adds complexity (Phase 4 cleanup)
5. **No split-layer objects**: Tree trunk and canopy render as single unit (Phase 3)

---

## Breaking Changes

None. All changes are backward-compatible:
- Existing mods work without modification
- Legacy rendering path maintained during transition
- Visual Pack system extended, not replaced

## Migration Notes

**For Mod Authors:**
- No action required for v0.1
- Objects automatically get height classification via pattern matching
- Future v1.0 will introduce Visual Pack v2 schema for explicit configuration

**For Engine Developers:**
- Use `EntitySprite` type for new renderables
- Call `registerEntity()` / `unregisterEntity()` for lifecycle
- Access `depthSorter` for manual depth queries
